# Harness 少样本质量复盘 V1

## 范围

本方案落实已确认的少样本方向，优先于此前的完整参数实验平台规划。保持原有日更缓存和真值跟踪，不为凑样本调用股票分析，不自动调参，不新增 LLM 调用。

本版先解决“周报是否诚实、具体问题能否复现”：

1. 只读已有数据库，区分本周报告、累计报告、股票日期组合、各期限结果行，绝不把它们叫作同一批独立样本。
2. 周报主输出改为质量复盘，不再用旧评级命中率、方向取反 PnL 或 n>=5 来证明投资能力。
3. 检查已归档报告的价格、摘要、WAIT 与仓位矛盾，以及旧评价误把 WAIT 当持仓、美股套用 A 股基准的口径风险。
4. 分开显示任务日志、采集失败、已经到期未完成和缺少到期日。没有到期日不能证明“尚未到期”，不得给数据健康全绿。
5. 提供可定位的案例、确定性修复建议和验收条件；保存证据指纹，显示相比上次成功推送新增、变化和已消失的问题。
6. 无新证据仍可发送轻量定期摘要，但标注不需要重复深度复盘。不启动付费模型。

## 实现边界

- 新增 `tradingagents/harness/quality_review.py`：只读 SQLite 的统计、规则审计、案例和文本渲染。
- 修改 `weekly_review.py`：调用质量复盘，保留飞书发送适配；增加 `--no-notify`、`--db-path`、`--output-dir`，便于安全冒烟。
- 旧 `backtest.py`/`review.py` 保留手动研究能力。旧报告入口添加局限说明，不删除或改写历史数值。
- 不改 `main.py`、不迁移生产数据库、不改变报告评级和策略参数、不新增定时任务。
- 已有数据库的 Git 标签只展示为“归档版本记录”，不声称已经记录生成时完整配置。未归档的任务也无法凭此数据库统计，必须披露。
- 本版不声称完成新 3 日/12 月评价、成交模拟、快照重放、LLM 提案和收益验证。这些仍是后续能力，不以旧 T+5/T+30 替代。

## 数据与状态

最近七天按上海自然日闭区间 `[今天-6天, 今天]` 统计；报告时间按已有本地时间解释，SQLite 的无时区 `fetched_at` 按 UTC 转上海日期。

每个问题包含规则 ID、问题层次、关联报告/结果 ID、最近发生日期、处理建议和回归验收条件。旧缺陷不能算成本周新增报告失败。股票日期组合仅用于提示重复，不视为已去除所有相关性的独立样本。

复盘状态基于报告、结果、问题内容，而非周报生成日期；正常真值更新的采集时间变化本身不触发深度复盘。仅在推送成功后更新“上次已通知”基线；预览和发送失败不消耗变化提醒。

到期日缺失仅标“到期状态未知”，不凭自然日粗估交易日、也不篡改原 `not_due`。本版负责暴露问题，后续独立修复真值时钟与数据源。

## 验收

- 使用 `.venv` 标准库 `unittest`，不因当前环境没有 pytest 而临时增加生产依赖。
- 构造 WAIT=0、WAIT>0、长期看多但短期未预测、重复报告、过期未完成、到期日缺失、美股基准错误、历史归档失败等夹具。
- 验证数据库字节不变，预览不发消息、不更新已通知基线，推送失败保留待提醒状态。
- 用当前真实数据库只读冒烟，生成手机友好的 Markdown/JSON 样例；不调用 LLM、行情 API 或股票分析。
