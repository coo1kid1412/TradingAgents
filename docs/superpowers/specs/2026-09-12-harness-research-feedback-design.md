# Harness 研究复盘与参数实验平台优化规划

日期：2026-09-12

状态：设计提案，尚未实施；本次不改生产参数、不改定时任务。

后续范围调整：少样本阶段优先执行 `2026-09-12-harness-small-sample-v1-design.md`。本文件保留为长期路线，不代表已实施完整实验平台。

## 1. 目标与推荐路线

将 harness 从“按历史评级统计涨跌的周报脚本”，升级成 TradingAgents 的研究质量与迭代实验平台。

每轮复盘回答五个问题：哪里有问题、证据是否可靠、应该改数据/参数/提示词/协作流程中的哪一层、怎样验证、是否达到上线条件。

推荐渐进式实验闭环：

```text
实际分析与当时输入留档
  -> 代码计算到期结果、数据质量与分层指标
  -> 形成正反案例和问题证据包
  -> LLM 提出可验证的迭代假设
  -> 代码执行受控参数实验，必要时小规模重跑受影响 agent
  -> 样本外验证与前瞻影子运行
  -> 通过门槛后形成 PR，保留回滚版本
```

只修周报统计不足以支持调参；直接做自动寻优、自动改 prompt 则超出现有样本的支撑能力。本方案保留现有 Python + SQLite + 周报入口，不引入多 agent 优化团队、在线强化学习或新的后台服务。

核心分工：代码负责真值、计算、实验、约束和验收；LLM 负责理解证据、提出假设、设计流程改进与解释取舍。LLM 不自行计算胜率，也不把自己的确信当成实验结果。

## 2. 现状与必须先修的偏差

以下来自本机 2026-09-12 的代码、数据库与周报，不是新策略回测结论：

- 周报 1118 个“样本”实际是跨观察期限的结果行，对应 291 份报告、215 个股票日期组合；不能当作 1118 次独立决策。
- 已评分报告中，数据库标记 `a3f4cd8` 的仅 3 份。旧报告批量归档会读取归档时的 Git 版本，因此历史版本标签也不全可靠。
- T 期限的 291 份报告里，162 份动作是 WAIT，但方向评价仍主要由长期评级推导。
- `signed_pnl_pct` 把看空后的跌幅取反，称为收益；它没有证明用户做了空头交易，也不是可执行策略净收益。
- 现有 T、T+1、T+5、T+30 没有直接对应用户关心的未来 3 个交易日和一年判断。
- 美股也使用沪深 300 基准与 A 股时间窗；部分过期美股真值仍被标为 `not_due`。
- `review.py` 的最小分组样本 5 被周报称为“显著样本量”，并不构成统计显著性证明；大量重叠切片会重复报警。
- 尚无可靠的实际配置快照、冻结实验协议、候选版本对照及前瞻验证链条。

因此，现有命中率只能用于发现待检查案例，不能直接推出“量能门槛应从 1.3 调到 1.1”或“某个 agent 应降低权重”。

## 3. 三套独立评价，不再用一个命中率覆盖所有判断

### 3.1 短期预测：未来 3 个交易日

- 评价明确记录的短期上涨/下跌/震荡预测，不拿 12 个月评级替代。
- 初版把报告可用后第一个完整交易日定义为 S1，以 S3 收盘结算未来 3 个交易日。预测收益使用报告中可验证的事前参考报价，披露报价时点；执行收益使用可成交时点，两者不能混算。过期报价或无同时点基准的样本不进入正式收益比较。
- “数据不足”和“未作预测”记为弃权，单独披露覆盖率，既不算预测错误，也不算成功。
- 输出各类准确率、混淆情况、预测覆盖率、收益分布和不确定区间；方向与超过某个涨跌幅是不同指标。
- 如报告真正给出了事前数值概率，才做概率校准；不将“信心中等”擅自换算成 60%。
- 分市场、分析时段、版本、数据质量和事前市场状态统计；不以跌完后才知道的“熊市”标签指导当时决策。

### 3.2 交易建议：现在该不该做、条件触发后怎么做

- 分开新建仓与已有持仓。WAIT 不等于看跌，也不等于开了多单；HOLD 不自动等于预测横盘。
- 没有真实持仓输入时，只评价明确的新建仓建议。已有持仓的减仓建议保留条件分析，不编造买入成本、仓位或盈亏。
- 未触发买入条件不虚构成交。既报告避免的下跌，也报告相对预先选定基线错过的上涨；“永远不买”不能被评为最优。
- 操作实验至少对照当前策略、同起点固定持有与现金，使用一致资本预算、期限与费用口径；单股建议的结果分布不冒充真实组合净值。
- 区分“建议收益代理”“模拟成交净收益”和“真实账户收益”；没有账户成交记录就不展示第三项。
- 初版只有日线时，模拟限定为报告可用后下一可交易时点开始的日频模型，并标注非真实成交。盘中限价成交、跳空、停牌、涨跌停无法确定时标为不确定，不能仅凭价格触及就认定成交。
- 同一根 K 线同时触及止盈与止损，不猜先后；输出上下界或不纳入确定成交指标。费用、滑点、A 股 T+1 与交易限制纳入版本化规则。

### 3.3 中长期研究：3、6、12 个月

- 分别跟踪长期评级、目标价区间、相对市场表现及可证伪的业绩/催化假设。
- 月份按日历月目标日映射到对应市场后续交易日，不将 30 个交易日冒充一年。
- 未成熟的 12 个月样本显示“尚未到期”，可以提前跟踪已披露业绩和催化兑现，不能把这些代理指标当作一年投资效果。
- A 股与美股使用事前固定的各自市场基准；板块基准作为辅助。股票与基准的收益锚点、复权、分红口径必须一致。
- 结论只适用于实际分析覆盖的股票集合；当前用户自选样本不能代表全部 A 股或美股，也不能忽略退市、停牌与失败分析。

## 4. 运行档案与可追溯性

新增轻量运行清单，分析开始时建立、结束或失败时补齐。继续使用现有 SQLite 与报告目录，采用增量迁移，不覆盖历史原始报告。

每次至少记录：

- `run_id`、市场/时区、数据截止时间、报告实际可用时间、运行成功或失败及失败阶段。
- 生成时 Git 版本、工作区是否有未提交改动、相关代码内容指纹；不能将归档时 HEAD 当成报告生成版本。
- 实际生效的参数、配置指纹、每个角色的模型/provider、支持并实际发送的推理设置、prompt 与交接协议版本。
- 各输入的来源、业务发生时间、公开可得时间、抓取时间、价格类型及有效快照引用。仅有内容哈希但没有原始输入，不算可重放。
- 子 agent 的最终核心判断、事实证据 ID、假设、反证、待核实项，及 RM/PM 的采纳、拒绝或未解决状态。
- 每个角色的调用次数、输入/输出/可获得的推理 token、耗时、重试/修复次数；成本按配置的计费表估算并标注版本，不可得时标未知。

不保存密钥、完整环境变量或隐藏思考原文；延续现有精简交接设计。实验需要的是可审计的事实、判断与依据，不是完整思考过程。

旧数据按 `legacy / partial / reproducible` 分层。能从原始资料确定的才回填；缺少事前配置或输入的记录只用于问题发现，不参与正式参数晋级证据。

## 5. 超参数如何管理与验证

### 5.1 参数范围与优先级

按实际代码建立白名单，不把所有常量一次性迁移：

- 第一优先级，买入时机：`profile_calc.py::compute_short_term_structure` 的突破量比门槛、缩量标准、ATR 距离带。先研究信号确认是否过严、是否增加假突破。
- 第二优先级，资金流与因子：`capital_flow_utils.py` 的持续流出/承接阈值、`factor_calc.py::DEFAULT_FACTOR_WEIGHTS` 的权重。研究信息是否重复、是否给估值或短期资金过高权重。
- 第三优先级，交接与资源：`handoff.py::ROLE_BUDGET_CHARS`、`main.py::_build_config` 的实际辩论轮数、`role_policy.py` 的角色模型/推理/输出预算。研究质量、成本与延迟的取舍。
- 最后评估估值体系：`profile_calc.py` 的 PEG 增长折扣、区间和风格权重。需要独立的中长期证据，不能用 3 日涨跌优化 12 月目标价。

现有默认因子权重为动量 0.12、价值 0.22、质量 0.22、成长 0.18、低波 0.05、反拥挤 0.09、资金流 0.12。记录这些值是为了建立基线，不表示它们已经最优或应该立即改变。

参数定义包括类型、默认值、允许范围、影响环节、相互约束、版本与变更原因；必须通过真实调用链注入并记录最终生效值，不能配置里改了但运行仍读硬编码。

### 5.2 不允许拿来“刷分”的项目

- 交易日历、价格真值、复权方式、数据时效和已验证的亏损禁入约束，不作为收益寻优旋钮。
- 保留现有市场风险系统的职责，不让单股回测为了增加买入次数随意放松大盘风险门控。风险模型自身优化另立协议。
- 评价标签、涨跌幅口径、费用、基准和样本筛选在实验开始前固定；修改评价规则必须发布新评价版本，不能与旧分数直接比较。
- 不因澜起、中际旭创等某一只股票后来上涨，倒推应给它更宽松的流程。

### 5.3 首个建议实验

问题：量能确认是否使健康突破的介入过晚，同时它是否确实减少了假突破？这是待验证假设，不是已证实问题。

- 当前基线：突破确认使用当日成交量 / 20 日均量 >= 1.3。
- 候选：只比较 1.1、1.3、1.5；固定其余逻辑、市场门控和评估协议。
- 优先使用完整日线的报告，避免把盘中部分成交量与完整日均量混作同一实验。无合格样本则继续采集，不强行寻找“最优”。
- 先做不调用 LLM 的局部敏感性分析：哪些结构/入场判断改变，变化是否只出现在临界样本，风险禁入是否仍有效。
- 局部重算不等于最终策略回测。如果变化会影响下游 LLM 的 RM/PM 判断，必须重算受影响链条或进行前瞻影子对照，不能沿用旧 PM 结论声称已验证策略收益。
- 最终比较固定日频模型下的配对净收益差、尾部损失、假突破、参与覆盖率和等待机会成本；不单独最大化命中率。

后续每轮只改一个参数族，最多两个参数、每项最多三个预注册取值。记录全部候选与失败实验，不只保留获胜者。

## 6. 实验与防穿越协议

1. 冻结实验定义：假设、候选、数据截止、样本范围、主要指标、风险/成本/覆盖率边界、检查次数与停止条件。
2. 时间顺序划分探索、验证与锁定测试。不能随机打散相邻交易日；跨边界的重叠标签需要剔除并按对应预测期限留出隔离区。
3. 保留全部运行用于工程质量统计；投资评价按事前定义的决策时点去重，同股同快照的重复分析不增加独立样本数。配置对照则保留配对关系。
4. 基线与候选使用相同合格样本。按股票与时间/市场事件簇处理相关性，报告配对差值及不确定区间，不以 `n >= 5` 宣称显著。
5. 评价范围涵盖所有候选；同一锁定测试集看完结果后再调参数，该测试集即失去最终检验资格。不得每周重复试到通过。
6. 事前特征只能读取当时已公开并可得的数据；事后价格与复盘材料位于独立评价层，不能注入预测重放的 agent 输入。
7. 当前 LLM 可能已学到历史事件。因此拿今天的模型重跑旧日期，即使限制工具日期，也只能作为诊断实验，不能声称严格无穿越。策略晋级依赖前瞻记录与影子运行。
8. 显示两类证据：代码/契约回归证明实现正确；样本外与前瞻对照评价策略是否更好。冒烟三只股票不能替代统计验证。

研究参数晋级至少需要完整可追溯输入、通过数据/契约检查、两个预先定义的不重叠短期评价窗口，以及达到预注册的收益改善和风险非劣边界。实际边界、窗口长度与样本量依据探索期的方差和最小有意义效应确定，在验证前冻结；它们不是任意的“20 次就显著”。

当前最新版本样本很少，第一版允许并应当输出“证据不足，暂不调参”。一年判断未到期不阻止短期工程交付，但不得宣称长期策略已验证。

## 7. 从复盘生成可实施的迭代方案

### 7.1 先定位层次，再建议改法

- 数据问题：现价、新闻公开日期或美股真值错误，优先修数据，不能靠降低信心掩盖。
- 提取/契约问题：短期趋势或动作丢失、摘要格式失败，优先补校验和恢复测试。
- 参数问题：某个门槛在多个独立样本中持续产生可比较的偏差，才进入参数实验。
- 协作问题：分析师证据准确，但在交接中丢失、被错误否决，或未影响其负责的决策变量，改交接与决策流程。
- 资源问题：增加辩论/上下文仅增加成本、没有改善证据完整性或决策质量，提出预算对照实验。

### 7.2 agent 贡献不能只看有没有被引用

基本面对应盈利与长期价值；市场分析对应短期趋势和结构；新闻对应催化与事件；舆情对应拥挤和分歧；风险对应限制；RM 对应投资判断；PM 对应动作与仓位。

沿用现有研究证据和贡献台账，检查各角色负责的信息是否传递并影响对应变量。引用率只是可追溯性指标，不是贡献的因果证明；正确的风险反证也可能让评级不变。

仅对有争议的少量案例，使用冻结输入做“替换/移除一项证据后重跑受影响下游”的消融检查，并披露 LLM 随机性与历史知识限制。不能因一次删掉 agent 后评级没变，就认定这个角色无用。

### 7.3 每条迭代建议的交付格式

必须包含：问题 ID、证据等级、涉及版本/市场/期限、合格及独立样本数、正例和反例、疑似根因、建议改动、影响角色/参数、验证方案、主要指标、风险边界、费用预算、回滚方式。

允许结论是修 bug、启动实验、继续观察或否决候选。禁止给出没有证据来源的胜率改善承诺。代码负责验证样本 ID 和数值，LLM 只组织判断与方案。

周报最多展示三个去重后的高优先级问题；按可靠性、影响与可行动性排序，不堆叠 168 个重叠告警。

## 8. 日常运行、费用与交付形式

- 保留每日 21:00 数据更新和周六 10:00 周复盘的现有调度，本次不新增任务、不影响现有缓存预热，也不改大盘预警推送策略。
- 每日路径纯代码：记录运行、补真值、识别到期缺数据、更新指标。`not_due` 只表示目标日期尚未到；到期缺数据、源不支持、抓取失败分别列出，重试有次数和退避限制。
- 健康度分开显示“任务成功、数据新鲜、样本覆盖、评估完成、推送成功”。脚本退出 0 不自动等于评估数据健康。
- 周复盘按证据包指纹去重；没有新成熟样本、重要失败或实验进展时，不新增 LLM 分析。日常定期统计可照常发送。
- 建议初始增量预算：每周最多一次 LLM 复盘和一次格式修复；精选输入最多约 12000 token、可见输出最多约 3000 token。推理和重试也计入总预算，不能把可见输出上限当作费用上限。
- 自动的付费 agent 消融/历史重放默认关闭。确需验证时，每周最多 6 次增量模型调用且计入统一 token/金额上限；此限制只能覆盖少量案例，不能代表完成了全链路多样本验证。
- 有可靠计费配置才启用金额控制；成本信息缺失时仍强制 token/调用硬上限，费用显示未知。触及上限则停止新增调用，保留确定性周报，不牺牲主分析的可用性。
- 主分析继续使用统一模型配置；harness 不另写固定模型或密钥，不因 DeepSeek 余额变化而需改代码。

飞书摘要采用短段落，不依赖宽表格：本周新增/成熟样本、当前生产版本、数据质量、短期预测/操作/长期研究各自结果、本周前三问题、实验状态和下一步。全文留在本地报告，并复用已有可用的飞书附件/文档交付渠道；不要把本机路径包装成手机可打开的链接。

## 9. 分阶段交付

### 第一阶段：可信复盘底座

建立生成时运行档案，修正 WAIT/长期评级混评、样本数、市场日历/基准与到期缺数据分类，增加 3 个交易日和 3/6/12 个月的跟踪协议。先提供准确的周报和问题清单，不调整策略默认值。

验收：相同输入可重复算出相同结果；没有持仓不虚构收益；旧版和当前版分开；长期未到期不会冒充成功；数据坏了周报不能全绿。

### 第二阶段：一个参数的实验闭环

打通量能确认门槛的参数白名单、配置留档、局部重放、候选对照、样本外协议与前瞻影子记录。先验证链条可运行，不承诺一定找到更优值。

验收：能给出“哪些决策因哪个参数改变、代价是什么、能否晋级、为何证据不足”；基线默认行为保持不变，未经晋级的候选不改变用户报告。

### 第三阶段：受预算约束的迭代提案

接入每周一次的 LLM 证据复盘、agent 信息传递诊断、结构化提案和验证清单。验证稳定后才逐步扩大参数族和小规模消融范围。

验收：每条建议能定位证据和实现位置，包含反例、验收与回滚；费用可查、可限；无新证据时不重复调用。

三个阶段形成第一轮完整 V1：可信评价 -> 一个可验证的参数实验 -> 一份有证据的迭代建议。长期标签继续随时间积累，不需要等一年才交付平台。

## 10. 上线与非目标

- 每阶段独立 PR，先通过 `.venv` 下的确定性回归，再做隔离数据副本冒烟；禁止实验写入正式报告或污染生产统计。
- 工程 bug 修复与策略改动分开记录。策略候选只有满足预先批准的晋级协议，才走已有授权的分支、PR、测试和合并流程；不把“单元测试通过”当成投资效果通过。
- 所有上线保留上一套代码/参数/评价协议与对照结果，回滚恢复整套配置，而非临时散改多个常量。
- 暂不购买新数据权限。先使用现有日线和报告快照；缺少分钟级、历史公开时点或退市数据的能力明确降级，不能承诺精确盘中成交回测。
- 不保证避免所有亏损，不以全市场选股能力包装用户自选样本结果，不自动放松亏损禁入或风险门控。
