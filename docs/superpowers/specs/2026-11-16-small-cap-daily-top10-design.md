# 小市值策略：每日 Top10 候选选股模块需求 V1

状态：需求草案，待用户在新会话确认；不是收益已验证的策略，不授权自动下单。
初稿日期：2026-11-16；审读修订：2026-11-17（会话日期）；所有策略时间、交易日和调度均按 Asia/Shanghai。

## 1. 用户目标与交付边界

用户已确定：在 TradingAgents 同一项目中新建独立模块、另开会话推进；根据指定小红书笔记的逻辑，每日选出 Top10 A 股，尤其防止数据穿越。

V1 交付是：每个 A 股交易日收盘后，以封存的数据快照生成下一交易日的最多 10 只研究候选，提供入选依据、风险状态、数据时点及完整排除日志。Top10 是候选排序，不代表同时买入 10 只，也不代表收益概率排名。

本文件中标记为“工程默认”的选项是设计提案，不是作者原话或用户已确认的交易规则。用户确认本文件后，构建者可按默认项独立实现；不得私自换口径、靠回测表现调整阈值。

不做：券商接入、自动交易、承诺收益、LLM 全市场选股、擅改主分析链路、自动启用生产定时推送。V1 不宣称复现原策略的真实收益；分钟级持仓/交易模拟另列 V2。

## 3. 实现方案选择

- 方案 A：新增确定性规则筛选器，独立快照/审计/报告，复用项目数据连接和通知能力。推荐并按此写需求，低成本、可回放，不依赖 LLM 输出稳定性。
- 方案 B：接入已有多 agent 图，逐股调用分析再选前十。成本高，且会改变市值排序的原始逻辑，不用于本模块 V1。
- 方案 C：直接复制完整交易/回测系统。原帖缺强弱市和成交等关键定义，不能称为忠实复现，推迟至 V2。

## 4. V1 筛选算法与默认口径

所有阈值集中在本模块配置；配置中记录 rule_version、各字段的 rule_origin 和参数哈希。

1. 股票域：历史时点已上市的沪深主板人民币普通股；按交易所/板块身份识别，排除 B 股、存托凭证、基金、创业板、科创板、北交所。不能只按当前代码前缀或今天的上市状态识别。
2. 排除当时已经生效的 ST/*ST、退市整理和已退市证券。未来才被 ST 或退市的股票，不能提前从历史股票池剔除。
3. 上市年龄：`data_date - list_date >= 375`，工程默认采用自然日；边界 375 天通过。原帖未区分自然日/交易日，本项必须展示为假设。
4. 总市值：工程默认用 data_date 的 total_mv，先将供应商的万元统一为人民币元，保留 `1_000_000_000 <= total_market_cap_yuan <= 10_000_000_000`。不得误用流通市值、今日股本或按今天价格回推历史市值。
5. 财务口径：工程默认采用“截至信息截止时点可验证的最新年度合并报表”，归母净利润 `n_income_attr_p > 0`、营业收入 `revenue > 100_000_000`，两者来自同一报告期、同一报表版本。不是扣非利润，不是 TTM，也不是把最近单季与全年混用。先按已可知的年度报告期末选最新期，再在该期内选当时可用的最新合并报表版本；旧年度后发布的更正不能挤掉更新年度。已知最新年度报告存在但关键字段不可用时，结果为 UNKNOWN，不退回上一年寻找盈利值。
6. 财务陈旧：工程默认报告期末距 data_date 不超过 550 自然日；缺失/过旧/不符合当前运行模式版本要求者标 UNKNOWN，不以 0、正值或更晚报表填补。前向封存与严格历史版本要求不同，见 §7.1。此阈值可配置但不得按收益调优。
7. 股价：用 data_date 正式收盘的未复权人民币价格，`0 < close <= 50`。不能用前复权价执行名义价格过滤。超过 50 元“不买”不等于本模块自动建议卖出现有持仓。
8. 工程新增的可用性规则：有可靠证据表明 data_date 停牌或正式当日成交量为 0 的证券可排除，并明确原因。接口漏行、行情晚到、截断或没有正式当日行情时为 UNKNOWN，不能假定停牌；按 §7.3 判断是否阻断排名。涨停/跌停股票不因该标志直接改变市值排名，但必须标注成交受限，不能宣称下个交易日可买到/可卖出。
9. 对通过验证的候选按 `(total_market_cap_yuan 升序, ts_code 升序)` 稳定排序，取前 10。不得由 LLM、技术评分、行业偏好或上涨结果重新排序。
10. 合格股票少于 10，只返回真实数量并标记 INSUFFICIENT；不放宽条件、不补入亏损股、不复制旧榜凑数。

年度报表口径是为了明确首版可实现边界，不声称等于作者口径。后续比较季度/TTM 必须另建 rule_version，不能覆盖旧结果。

## 5. 每日时钟、截止时点与交易语义

- 工程默认每日 19:30 中国时间启动，先收集当日正式日线、日指标、证券状态及已可见财务，再封存快照；`as_of_at` 为实际封存时间，不伪装成 15:00 或任务启动时刻。
- `data_date=T` 必须是交易所日历确认的交易日；`target_trade_date` 是 T 之后第一个实际开市日。不能直接加一天，也不能只看周一至周五。
- 前向任务必须在 target_trade_date 的中国时间 00:00 前封存；达到或跨过该界限返回 CUTOFF_EXPIRED，不自动改目标日期发布。此限制检验原决策快照的时点，不因今天已经晚于目标日就拒绝离线重放旧快照。
- 行情必须来自 T；T-1 缓存不能标为 T 的正式榜单。数据源晚到时允许有限重试，仍不足则发送数据异常，不发布“正常 Top10”。
- 非交易日可显示上一次榜单及原时间，但默认不生成新的榜单/预测，也不重复推送。盘中不以未收盘数据冒充这一策略版本。
- 周二 10:00 是原作者交易规则，不是每日选股的运行时刻；V1 只记录是否下一开盘日为周二，其他日的榜单变化不等于调仓指令。节假日是否顺延调仓未知，默认不自动顺延。
- 榜单是截至 as_of_at 的研究结果，不能保证包含封存后至次日开盘前的新公告或临时停牌；报告必须提示开盘前重核交易资格。
- 交易日历及其版本也随快照封存。证券状态筛选默认取 T 收盘的有效状态；封存前已经公开、但下一交易日才生效的状态变化另加醒目风险标志，不倒改 T 的状态。没有时间证据时不得推断生效或可知时点。

## 6. 风险状态与原帖未定义部分

V1 不持有真实/模拟仓位，不从候选名单推断用户已持仓，不能据此计算止损价或发出卖单。

- 每天仍可生成研究 Top10；若 target_trade_date 属于 1/4 月，标 `strategy_mode=SEASONAL_STOCK_AVOID`、`new_position_policy=BLOCK`，明确“仅研究观察，原策略窗口不新开股票仓位”。不能为了凑每日产出而隐藏避险窗口，也不自动购买货币 ETF。
- 其他月份标 `strategy_mode=RESEARCH_CANDIDATES`、`new_position_policy=NOT_EVALUATED`。筛选通过不等于已获准买入。
- 强弱市指标、指数、窗口和阈值没有原始证据：V1 `regime=UNKNOWN`，只并列展示“原帖强市前 3、弱市前 6”的情景名单，不自行认定当前应买 3/6 只，不虚构胜率或总仓位。
- 可只读附加现有市场风险快照，保留其 as_of、数据状态、生成版本及有效期；过期/历史时点之后生成的快照不用。外部快照不能替换作者未知的强弱市定义，也不改变 Top10 排序。
- 日内 14:00/14:50、涨停续持、开板卖出、止盈止损、货币 ETF 的具体代码/成本/触发优先级列入 V2，V1 显示“未实现”，不能声称风险已覆盖。

## 7. 防数据穿越：不可妥协的契约

每个输入事实记录 `effective_at`（何时生效）、`published_at/available_at`（何时可知）、`first_observed_at`（何时采集）、source、revision_id/hash；不混淆报告期、公告日与采集日。

### 7.1 财务信息与修订

- 同一报告期按已公开的版本取值；只允许 available_at 不晚于 as_of_at 的版本。实际公告日期优先于计划披露日期；不能仅因 end_date 早于决策日就使用该财报。
- 前向运行还必须满足 first_observed_at 不晚于 as_of_at，并且事实已进入该次封存清单。后来才采集的事实不能补进旧快照；不能把供应商的旧公告日期伪装成自己的更早观测记录。
- 只有公告日期 D、没有可靠分钟时点时，工程默认最早北京时间自然日 D+1 的 00:00 可用；宁可晚用，不能假定当日早盘就知道。
- 后续更正/重述单独保存版本，使用更正自身的公告/可用时间，不能继承原报表的旧公告日；不能覆盖旧值，重跑旧快照不能看到新版本。比较期重述只有在报告期映射及版本证据明确时才能更新对应旧年度的后续可见版本。
- 今天下载的历史报表即使附带旧公告日，也不自动证明该数值是当时版本。没有原始版本证据时，历史回放必须标记 `HISTORICAL_VERSION_UNVERIFIED`，不能声称严格 point-in-time，更不能展示为无穿越收益回测。
- 从部署日起持续封存的原始响应可用于向前积累可审计的每日候选；历史研究与真实前向信号分开存储、分别评价。
- 当前首次取得并封存的供应商响应，以内容哈希标识采集版本，可证明“现在看到什么”，允许作为当前前向输入；这不证明相同数值过去已可见。严格历史回放必须使用当时封存版本，或有可核验原始披露证据的对应版本；无法证明时只出隔离的诊断研究草稿，不得仅贴标签后照常发布正式历史 Top10。

### 7.2 证券池、行情及元数据

- 用上市/退市有效区间和当时状态重建证券池，不能只查询今天 list_status=L。
- ST、更名、板块迁移、代码变更、停复牌和风险警示使用历史生效记录。未知状态不能按“正常”处理；行业标签若只能取得现值，只作注明口径的展示，不参与历史筛选。
- 价格/市值必须具有同一 data_date，不允许 T 价格拼 T+1 股本；未来高低价、次日开盘、后验收益字段不得进入选择函数。
- 不复权价格用于 50 元过滤和未来成交模拟；收益计算另行处理公司行动，不能混用当前前复权口径进行历史名义阈值过滤。
- 不静默换供应商、不用今日名称给历史加 ST、不用全样本最优阈值，也不用当前大盘风险快照评价历史状态。

### 7.3 缺失值与 Top10 完整性

- `FAIL`、`PASS`、`UNKNOWN` 是不同状态；缺数据不能证明股票不合格。
- 逐阶段记录应覆盖数量、实际覆盖数量、未知代码及缺失字段，并验证接口分页/截断。不得把接口只返回的前 N 行当全市场。
- 任何尚不能排除的股票，若其市值缺失，或完整排序键 `(市值, ts_code)` 排在当前第十名之前，或其他未知信息可能改变边界，则榜单完整性为 BLOCKED；只可保留明确标注的诊断草稿，不能发布正式 Top10。
- 若已知完整排序键严格在第十名之后，缺失信息不可能改变前十，可带覆盖警告发布；同市值按代码顺序判断，需保存完整证明。少于十只时，任何仍可能合格的 UNKNOWN 都影响完整性。
- 明确已因板块/ST/年龄等可靠规则排除的股票，不要求继续补全无关财务；不能通过无关缺失阻断全部任务。

## 8. 输出与用户阅读方式

以 JSON 为结构化真值，Markdown/通知由同一对象确定性渲染；默认没有 LLM 调用。

运行级必需字段：schema_version、rule_version、rule_assumptions、run_id、mode、data_date、as_of_at、generated_at、target_trade_date、timezone、snapshot_id/hash、config_hash、code_version、status、ranking_complete、coverage、warnings、strategy_mode、new_position_policy、regime、rebalance_due、top10、exclusions_ref、delivery_status。

每行必需字段：rank、ts_code、当时名称、exchange/board、行业及其时点口径、总市值（元）、未复权收盘价、上市天数、财报期间/版本/可用时间、归母净利润、营收、逐条规则 PASS 及证据引用、已知成交受限标志、较上一成功榜单的排名/新增变化。缺行业可显示未知，不得伪造赛道或概念。

通知首屏依次展示：

1. “小市值研究候选 Top10｜行情 T｜面向下一交易日”。
2. 数据截止、榜单完整性、是否避险窗口；醒目注明“候选不是买入指令”。
3. 每只股票一个短条目：代码名称；市值/价格；盈利与营收期间；警告。避免手机端窄表格。
4. 新增/移出名单、缺失与待补证，最后说明 3/6 情景和周二调仓未执行。

移出榜单不是自动卖出；无前一成功可比快照时显示“首次/不可比较”，不虚构变化。生成成功与推送成功分开记录。

## 9. 模块边界、运行入口和持久化

建议新包 `tradingagents/strategies/small_cap/`，与单股 agent 图、harness 复盘库隔离。可在实施计划中合并小文件，避免为模式而过度分层。

- `config/domain`：可验证配置、带时间/版本的事实与结果模型。
- `data_source/repository`：Tushare 适配、PIT 查询、原始响应封存、原子落盘。
- `selector/service`：纯函数筛选排序与编排、覆盖证明、日历与状态机。
- `reporting/cli`：同源 JSON/MD、预览、显式通知与有限重试。

预期 CLI：`.venv/bin/python -m tradingagents.strategies.small_cap run --data-date YYYY-MM-DD --no-notify`。历史回放入口必须显式带 `--as-of`，只能消费符合时间契约的快照，不允许借当前接口“悄悄补历史”。命令最终以实施计划为准。

独立数据目录建议 `strategy_data/small_cap/`，报告 `reports/small_cap/<data_date>/<run_id>/`；原始数据/凭证不提交 Git。快照不可变；更正重跑产生新 run_id，保留旧报告，禁止覆盖历史真值。

独立 SQLite 或现有合适的持久化组件记录运行、版本、选择、排除及通知幂等键；不得迁移/污染现有交易报告数据库。相同 frozen snapshot+config 的选股 payload/hash 必须一致；generated_at 等运行元数据不参与选股哈希。

API 超时/限流有限重试，错误保留原因；缓存必须具有日期与版本。通知按 `(rule_version, data_date, snapshot_id, recipient)` 幂等；失败可重试，不能为重发消息重新选股。

本轮仅写需求并建立新会话，不启用 cron、Codex 自动化或飞书推送。模块离线/数据实测验收通过后，新会话再落实每日任务与经确认的接收人；调度必须显式指定中国时区并适应宿主机时区变化。

## 10. 数据能力与权限核验

沿用项目 .env 的 Tushare 连接但绝不打印密钥；用户拥有 5000 积分档位，不等于所有实时/分钟接口均可用。

首轮只读 preflight 验证：股票清单含历史状态、交易日历、daily、daily_basic、财报及更名/ST/停复牌有效记录、分页与历史覆盖。记录可访问、无权限、空数据、历史未覆盖，不能混为一个失败。

Tushare 利润表文档列出 income / income_vip 及公告字段；日指标 total_mv 的单位为万元。接入必须以真实字段/权限小样本确认，不复用已有单股“当前估值”文本计算历史榜单。

若缺部署前财报历史版本，不阻塞建立真实前向封存能力，但必须关闭“严格历史回测已验证”的声明；当日核心数据缺失按 §7.3 的排名影响证明处理，不另设互相冲突的全局忽略或阻断规则。V1 不为选股采购分钟行情，也不自动付费扩权。部署前全历史补建、收益研究不是 V1 验收前置条件；当前选择所需的数据证据不能豁免。

## 11. 必须通过的验收测试

使用现有 .venv 和离线 unittest；网络/LLM/飞书默认拦截。

1. 阈值边界：市值 10/100 亿通过、越界失败；价格 50 通过、50.01 失败；利润 0、营收恰好 1 亿失败；上市 374/375 天边界正确。
2. 注入未来盈利公告、次日价格/股本或未来风险快照，历史选择哈希完全不变。
3. 财报更正版本只影响可用时间之后的运行；缺版本证据时不能变成严格历史模式。
4. 公告只有日期时当日不可用，D+1 可用；时区跨日、夜间采集封存时刻准确。
5. 未来才 ST/退市的公司不会从更早样本消失；当时已经 ST/不合格的会被排除。
6. 行情 T-1、未收盘、停牌、分页截断和关键字段 UNKNOWN 的覆盖证明/阻断行为正确。
7. 低市值潜在合格者财务未知时不能假称 Top10 完整；第十名之后缺失不影响结果的情况有证明与警告。
8. 少于十只不补齐；市值并列稳定排序；不混市场、货币及历史行业标签。
9. 跨年/跨月/节假日 target_trade_date 正确；一/四月目标开盘日的 BLOCK 不会被上一数据日月份覆盖。
10. 每日榜单不自动变为每日调仓；强弱市未知时不输出确定的 3/6 只买入指令。
11. 同快照可离线重放，原始快照与历史报告不可变；中断不能产生半份成功报告。
12. 无通知模式不发消息；发送失败可重试且不重算榜单；不存在任何 LLM 或券商调用。
13. 同市值的未知股票按代码先后正确阻断/放行；无行情的接口漏行不能假装有证据的停牌。
14. 新年度报表优先于旧年度的后发更正；最新年度字段不全不能退回较旧盈利年度；首次当前观测不能被回填成历史观测。

验收分三级：离线规则测试通过；真实数据 preflight/一个完整交易日快照生成通过；开启每日调度/通知后的运行验收。三者不得互相冒充。首版是否赚钱不属于可用性验收，不能以选出 10 只证明有效。

## 12. V2 与待补证清单

V2 才做完整交易模拟：强弱市定义、等权/总仓位、周二节假日顺延、涨停续持与日内目标池、卖出/补仓顺序、止盈止损成本基准、ETF 代码。补证前只能比较明确标注的假设版本。

回测须另建成交层，处理 T+1、未成交/部分成交、跌停无法退出、手续费/印花税历史变更、滑点与容量、公司行动。不能用当日收盘数据在 10:00 成交，日线近似不得称为原策略盘中复现。来源：https://docs.static.szse.cn/www/lawrules/rule/trade/W020260424690713155663.pdf

研究顺序：同一历史可验证股票池的固定 3/6 只基线，再逐条加入额外规则并做样本外/滚动验证，报告回撤、换手、成本、暴露、覆盖和无法成交案例。不让 LLM 看未来收益来调筛选条件；小盘 ETF 不是这组集中持仓的等价替代。
